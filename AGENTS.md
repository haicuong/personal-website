## 🏗 Architecture Overview

**Multi-Page App (MPA)** built with Vite in `appType: "mpa"` mode. Each HTML page is independently bundled.

### Build Pipeline

```
npm run build:
  1. tsx build-projects.ts     → Generate projects/posts/ + projects.json
  2. tsx build-blog.ts          → Generate blog/posts/ + blogs.json
  3. npm run lint:css           → Stylelint check (zero warnings)
  4. tsc                         → TypeScript type checking
  5. vite build                  → Vite bundling and optimization
```

Content generation modules use a shared `buildContent()` function that:
- Parses Markdown with YAML frontmatter (gray-matter)
- Converts Markdown to HTML (marked)
- Applies syntax highlighting (Shiki)
- Generates individual post/project HTML pages from `blog/templates/post-template.html`
- Creates metadata JSON files

### Page Structure

| Page                               | Purpose                                                | Generated? |
| ---------------------------------- | ------------------------------------------------------ | ---------- |
| `index.html`                       | Home / Landing page                                    | No         |
| `blog/index.html`                  | Blog index; loads metadata from `blogs.json`           | No         |
| `blog/posts/<slug>/index.html`     | Individual blog post pages                             | **Yes**    |
| `projects/index.html`              | Projects showcase; loads metadata from `projects.json` | No         |
| `projects/posts/<slug>/index.html` | Individual project pages                               | **Yes**    |
| `404.html`                         | Error page                                             | No         |

### Metadata & Routing

- **Blog metadata:** `public/blogs.json` — Generated by `build-blog.ts`
  - Contains: `slug`, `url`, `title`, `date`, `description`, `tags`, `coverImage`
  - Routes to: `/blog/posts/<slug>/`
  
- **Project metadata:** `public/projects.json` — Generated by `build-projects.ts`
  - Contains: `slug`, `url`, `title`, `date`, `description`, `techStack`, `repoUrl`, `liveUrl`, `coverImage`
  - Routes to: `/projects/posts/<slug>/`

Both metadata files are loaded client-side by `src/scripts/cardRender.ts` to render dynamic card components.

## 🔧 Development Conventions

### TypeScript Configuration

- **Target:** ES2023 with DOM library
- **Module resolution:** `bundler` (Vite/TypeScript 5+ convention)
- **Strict mode enabled:**
  - `noUnusedLocals` — Flag unused variables
  - `noUnusedParameters` — Flag unused parameters
  - `erasableSyntaxOnly` — Ensure all syntax is removable
- **Include:** `src/` directory
- **Lib:** Browser + Vite client types

### Web Components

**Location:** `src/scripts/components.ts`

Defined components:
- `<site-header>` — Navigation header with Home, Projects, Blog links
- `<site-footer>` — Footer with contact/social information

**Usage:**
- Imported globally via `main.ts` on all pages
- Auto-registered via `customElements.define()`
- Use as: `<site-header></site-header>` and `<site-footer></site-footer>`
- Defined once in `components.ts`; do NOT redefine or re-import

### Styling System

- **Framework:** Tailwind CSS v4 via `@tailwindcss/vite` plugin
- **Typography:** `@tailwindcss/typography` plugin for Markdown content styling
- **CSS file:** `src/styles/main.css`
  - Tailwind imports
  - Base layers: `body`, `main`, `site-header`, `site-footer`
  - Dark mode support via CSS `prefers-color-scheme`
  - All base styles use Tailwind utilities or semantic selectors

**Best practices:**
- Use Tailwind utility classes directly in HTML
- Avoid custom CSS classes (except necessary base layers)
- Use `dark:` prefix for dark mode variants (e.g., `dark:bg-gray-900`)
- Mobile-first approach: no prefix for mobile, `md:` for medium screens and above
- Responsive breakpoints: `sm:`, `md:`, `lg:`, `xl:` (Tailwind defaults)

**Linting:**
- CSS linter: Stylelint with `stylelint-config-standard`
- **Zero warnings policy:** Run `npm run lint:css` before committing
- Configuration: `.stylelintrc.json` or Stylelint config in `package.json`

### File Naming & Organization

- **HTML files:** Semantic names reflecting page purpose (e.g., `index.html`)
- **TypeScript/JavaScript:** camelCase (e.g., `cardRender.ts`, `buildContent.ts`)
- **CSS files:** kebab-case classes are avoided; use Tailwind utilities instead
- **Markdown content:** kebab-case slugs (e.g., `hello-world.md` → `/blog/posts/hello-world/`)

### HTML Standards

- Semantic HTML5 throughout
- ARIA attributes where appropriate for accessibility
- Root-relative asset paths (e.g., `/images/logo.svg`)
- Vite resolves paths correctly for MPA

## 📝 Content Workflows

### Blog Posts

**Source:** `blog/content/*.md` with YAML frontmatter

```yaml
---
title: "My Blog Post Title"
date: "2026-01-15"
description: "A concise summary for previews"
tags: ["typescript", "web-dev"]
coverImage: "images/blog/my-post/cover.jpg"
---

## Post content in Markdown...
```

**Generation:**
1. `build-blog.ts` triggers `buildContent()` during build
2. Parses each `.md` file, extracts frontmatter and content
3. Renders Markdown to HTML using `marked` with Shiki syntax highlighting
4. Generates `blog/posts/<slug>/index.html` from template
5. Creates `public/blogs.json` with metadata

**Supported code languages:** `javascript`, `typescript`, `html`, `css`, `json`, `bash` (via Shiki)

**Client-side loading:**
- `blog/index.html` lists blogs dynamically
- `cardRender.ts` fetches `blogs.json` and renders cards
- Each blog card links to generated post page

### Project Showcase

**Source:** `projects/content/*.md` with YAML frontmatter

```yaml
---
title: "My Project"
date: "2026-01-15"
description: "What this project does"
techStack: ["react", "typescript", "tailwindcss"]
repoUrl: "https://github.com/user/repo"
liveUrl: "https://project-live.com"
coverImage: "images/projects/my-project/cover.jpg"
---

## Project description...
```

**Generation:**
1. `build-projects.ts` triggers `buildContent()` during build
2. Same process as blogs, but generates `projects/posts/<slug>/`
3. Creates `public/projects.json` with extended metadata (techStack, URLs)

**Client-side loading:**
- `projects/index.html` lists projects dynamically
- `cardRender.ts` fetches `projects.json` and renders cards
- Cards display tech stack with hex color mapping
- Each project card links to generated post page

### Adding a New Page

1. Create `your-page/index.html` (or `your-page/subpage/index.html`)
2. Import shared CSS and scripts:
   ```html
   <link rel="stylesheet" href="/src/styles/main.css" />
   <script type="module" src="/src/scripts/main.ts"></script>
   ```
3. Use Web Components:
   ```html
   <site-header></site-header>
   <main>Your content</main>
   <site-footer></site-footer>
   ```
4. Vite's glob pattern in `vite.config.ts` automatically includes it
5. Built to `dist/` on `npm run build`

## 🔄 Build System Details

### Vite Configuration

**File:** `vite.config.ts`

```typescript
appType: "mpa"              // Multi-Page App mode
build.rollupOptions.input:  // All index.html + 404.html
```

Automatically discovers and bundles:
- All `**/index.html` files

## ⚠️ Common Pitfalls

1. **CSS Warnings:** Stylelint is zero-warnings strict. Run `npm run lint:css` before committing.

2. **Unused Variables:** TypeScript strict mode flags unused locals/parameters. Remove them or suppress with `// @ts-expect-error`.

3. **Generated Files:** Do NOT manually edit:
   - `blog/posts/**` — Regenerated on build
   - `projects/posts/**` — Regenerated on build
   - `public/blogs.json` — Regenerated on build
   - `public/projects.json` — Regenerated on build

4. **Asset Paths:** Always use root-relative paths (`/path/to/asset`), not relative paths. Vite resolves them correctly.

5. **Component Re-registration:** Web Components are defined once in `components.ts` and auto-imported on all pages. Do NOT re-import or re-register in individual pages.

6. **Code Language IDs:** Fenced code blocks must use supported Shiki identifiers (`javascript`, `typescript`, `html`, `css`, `json`, `bash`). Unsupported languages will not be highlighted.

- Profile picture: `public/profile-picture.jpg`
- Favicon: `public/favicon.svg` (responsive, respects color scheme)

## Common Tasks

### Add a New Page

1. Create `your-page/index.html` in root (or subdirectory)
2. Import the CSS and scripts:
   ```html
   <link rel="stylesheet" href="/src/styles/main.css" />
   <script type="module" src="/src/scripts/main.ts"></script>
   ```
3. Use `<site-header>` and `<site-footer>` components
4. Vite will automatically add it to the build output

### Add a Web Component

1. Define the class in `src/scripts/components.ts`
2. Call `customElements.define('component-name', ComponentClass)`
3. Already imported on all pages, so use it immediately: `<component-name></component-name>`

### Style a Page / Component

- Use Tailwind utility classes directly in HTML
- If necessary, add base layer styles in `src/styles/main.css`
- Run `npm run lint:css` before committing to ensure zero warnings

### Build & Deploy

- GitHub Pages or Vercel: Point to `dist/` folder after `npm run build`
- Build steps: CSS lint → TypeScript check → Vite bundle
- If any step fails, the build stops

## Potential Pitfalls

1. **CSS Linting:** Stylelint is strict (zero warnings). Run `npm run lint:css` locally before pushing.
2. **Unused variables/imports:** TypeScript strict mode flags these. Remove or suppress with `// @ts-expect-error` if necessary.
3. **Asset paths:** Use root-relative paths (`/path/to/asset`) in HTML. Vite will resolve them correctly.
4. **Component imports:** Web Components defined in `components.ts` are auto-registered globally on all pages. Do not re-import or re-define.
5. **Generated blog output:** `blog/posts/` and `public/posts.json` are regenerated by `src/scripts/build-posts.ts`; changes there will be overwritten and are ignored by Git.
